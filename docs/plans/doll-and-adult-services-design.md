# 性偶、玩偶与成人服务策划案（轻量版）

状态：轻量首版已接入代码，尚待用户体验验收；实际接入与入口见[实施记录](night-city-everyday-implementation.md)。

日期：2026-11-19

关联：[芯片日常使用](chip-everyday-use-design.md) · [超梦体验与正文调查](braindance-experience-design.md)

## 一、核心定位

**让成人服务成为夜之城可以反复接触的一部分生活，让从业者成为有自身经历和意愿的人。**

普通接待、熟客闲聊、下班后偶遇与私人关系都能独立成立。不要求每次接待都揭露秘密、遭遇危险或触发救援任务。

首版以项目已有的成年真人从业者和装有玩偶行为芯片的人物为主体。仿生或机械人偶如由角色资料明确设定，沿用其既定身份与实际能力；不默认所有“性偶”都是同一实体，也不另造机器人制造、买卖或人格编辑系统。

## 二、服务通过正文完成

**见面与询问 → 约定并明确接受 → 相处 → 正常结束或中止 → 结算与实际记忆。**

- 玩家可以只聊天、询价或改天再来；没有接受服务就不扣款。
- 约定明确提供者、实际价格、时长与服务范围，以及是否允许记录。临时改变范围需要重新获得双方接受，付款不代替持续意愿。
- 过程通过正文与自由输入展开。玩家可以继续、暂停、略写过程或结束，不设置动作清单、完成度、满意度或快感数值。
- 略写只改变叙述展开程度；约定正常完成时，钱与时间仍按实际服务结算。提前结束按已经明确的条件处理，不临时追加费用。
- 成年人物间的成人娱乐、商业亲密和私人亲密使用同一正文与人物规则；本案不编写露骨样文。描写方式继续交给写作预设，不叠加内置文风或感官配额。

相处能够平静地结束。人物工作之外的往来由本人态度、处境和共同经历决定，不随一次付款自动成立。

## 三、玩偶芯片只补必要事实

普通从业者不自动拥有玩偶芯片。对确实安装的人，先确定三个事实，再在后续场景中沿用：

| 事实 | 要解决的问题 |
| --- | --- |
| 实际安装与用途 | 装了什么、作用是什么；接入现有义体/设备资料，不能只写职业就凭空拥有 |
| 当前运行状态 | 本人清醒主导，还是既定范围内的芯片接管；启动、退出或中断须有真实发生的依据 |
| 本人能访问的记忆 | 接管期间本人是否有意识、事后能记起什么、能否查看既有日志，均按该人物与设备的固定设定 |

芯片接管、本人意识、设备日志是不同事实。结束接管不自动删除日志，也不自动让本人知道过程；事后看过日志可以知道记录了什么，不等于恢复了当时的亲历感受。

芯片只能利用实际取得的客户资料与现场输入，不能读取玩家未说出口的内心。芯片运行中的迎合不自动证明本人清醒时的意愿、信任或感情。设备权限也不等于超出本人约定任意接管的许可。

若玩家角色安装有关设备，仍遵守玩家控制权：实际启用、状态变化与身体影响有依据，模型不借芯片替玩家决定感情、台词或行动意图。

## 四、熟客关系与日常延续

- 反复使用同一人物和场所，保留名字、外貌、说话方式和已经建立的来往；不要每次重建一个相同职业的陌生人。
- 前台记得实际预约或买卖，本人记得其实际经历、获知或查看过的内容。不同人的客户资料不自动互通。
- 记具体小事：上次聊过的话题、明确说过的偏好、守约或爽约、一次玩笑。购买记录本身不推断私人偏好。
- 普通熟客关系可以持续存在；服务中的配合、工作之外的信任和私人感情分别发展，不用消费次数解锁恋爱。
- 人物有同事、朋友、忙闲、休息和工作之外的打算，可以拒绝、改约或只想吃完自己的夜宵。需要时用已有近况与场景承接，不模拟全店排班。
- 人物的私事可以普通、平静，不默认每个人都有犯罪把柄、悲惨身世或等待玩家解决的困境。

原有角色资料保留其具体经历和口吻。个别人物的窃录、勒索或危险遭遇不能泛化成整个职业的默认行为。

## 五、状态与结算保持轻量

| 必要内容 | 接入现有机制 |
| --- | --- |
| 人物身份、诉求、底线与工作地点 | NPC 人物卡、实际地点与既有关系 |
| 已安装芯片、当前模式与本人记忆条件 | 只补确实缺少的设备事实和人物状态，不增设人格配置平台 |
| 本次已经接受的服务与实际消费 | 现有报价、玩家授权、交易事件和世界时间 |
| 真实发生的相处与各自所知 | 共同记忆、已知事实和场景记忆；注明来源，避免把日志当亲历 |

同一笔服务沿用现有去重与事件结算，不重复扣费。询价和暂定意向不成立服务。钱、服务开始与相关交付保持一致，生成失败沿用现有检查点，不编造已经发生的互动或关系进展。

首版只按实际约定与活动记录游戏分钟；略写正常结束仍经过相应时间，单纯查看历史不耗时。无须新的钱包、订单平台、专门退款流程、成人面板或服务小游戏。

## 六、与芯片、超梦的联系

行为芯片的安装与启用由设备事实负责；本案负责它对人物意识、服务状态与记忆的具体影响，两处不重复记账。

只有实际具备录制条件并在正文中发生录制，才产生有关超梦或记录。接受服务不自动同意录制与传播；有记录也不自动让前台、客户或本人全都知道。作品的体验和后续查证接超梦策划，不把每次接待都变成调查素材。

## 七、实施与验收

实施顺序：先补必要的服务类型与真实行为芯片资料，再接通正文、交易与人物状态，最后补普通来往内容与记忆召回。服务成交沿用现有 `commerce` 与交易链，不借临时人情费或直接扣款绕过授权。

主要接入：`packages/content/src/` 的人物、地点与设备资料；`packages/core/src/systems/` 下的 `npc`、`cyberware`、`economy`、`commerce`、`inventory`、`memory`；正文仅增加事实与知情规则。

制作阶段不保留旧格式兼容层。每步执行 Git，有改动立即单独提交；不主动运行单元、集成或浏览器测试，仅保留必要静态检查，实际体验交给用户。

- [ ] 可以只聊天、正常消费并离开，不强加任务、危机或关系奖励。
- [ ] 回访仍是同一个人，能接续真实说过的话，也能保持普通熟客关系。
- [ ] 芯片接管前后本人、日志和经营者各自知道什么保持一致。
- [ ] 收费、耗时、保存与重试正确，询价不扣款，略写不凭空免去实际时间。
- [ ] 芯片迎合、商业亲密与本人真实意愿不混同，玩家控制权与人物边界成立。
- [ ] 启用写作预设时没有附加固定腔调、动作配额或统一文风。
