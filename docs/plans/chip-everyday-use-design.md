# 芯片日常使用与交换策划案（轻量版）

状态：轻量首版已接入代码，尚待用户体验验收；实际接入与入口见[实施记录](night-city-everyday-implementation.md)。

日期：2026-11-19

关联：[性偶、玩偶与成人服务](doll-and-adult-services-design.md) · [超梦体验与正文调查](braindance-experience-design.md)

## 一、核心定位

**让芯片成为日常会拿到、使用、收藏、借给别人和交出去的真实物件。**

芯片可以承载演出、教程、杂志、成人作品、私人便条、工作资料与情报，也可以是依赖硬件的功能组件。不要求每张都藏阴谋、带病毒或关联委托；买一张喜欢的作品、留一份维修资料、给朋友带个合集都能完整收场。

## 二、先分清三种用途

| 用途 | 首版怎么承接 |
| --- | --- |
| 资料与媒体载体 | 读取原文、播放内容、实际复制和交换；已读资料进阅读档案，超梦作品接超梦正文体验 |
| 技能或辅助功能 | 按具体芯片、接口、设备与人物经历确定真实辅助能力；购买和阅读不自动变成永久掌握一门技能 |
| 行为芯片 | 按实际设备安装、启用与适用范围起作用；玩偶接管和记忆边界接玩偶策划，不把它当普通资料一读即生效 |

能力来自已经确立的具体功能与使用条件，不新增法术书、通用装载槽、技能点或“读完加属性”。功能芯片可以提供实际帮助，也可以因设备不符无法使用；不要把所有芯片都做成一段收藏文字。

## 三、日常流程

**获得或购买 → 查看标签与已知来源 → 主动读取或使用 → 按需要收藏、复制、赠送、借用或交付。**

- 拿到芯片只建立实物和可见信息，不替角色自动阅读，更不因取得行为芯片就自动安装。
- 普通读取直接走正文或现有阅读入口；有实际防护且玩家尝试解密时，才接现有黑客与设备规则。
- 芯片中的超梦、音频或其他作品沿用相应内容规则，不在这里再做播放器。
- 实际交付改变持有人与位置，已经阅读过的知识仍保留。借出与赠送区分记录，借用约定复用已有承诺和记忆，不建借贷平台。
- 复制需要实际来源、可用设备与存储去向；生成有来历的承载对象或存储记录，引用同一内容，不复制出钱或其他无关资产。
- 修改内容必须真的发生，修改后的材料与原内容明确区分；不因玩家追问直接覆盖原文，也不建立通用版本管理系统。

买卖沿用已有报价、授权和物品交付。价格谈妥不等于玩家已经接受；重复请求不重复收费或交付。免费赠送与当面给别人看，按实际行为记录。

## 四、只补最少资料关联

| 内容 | 保存什么 | 复用方式 |
| --- | --- | --- |
| 芯片内容 | 稳定内容 ID、名称、来源、固定原文或功能说明、已经解开的部分 | 持久内容资料，重读引用同一份 |
| 实际载体 | 承载哪份内容、在谁手里、实际位置 | 现有 `inventory.objects` 与物品变更，不另建一套背包 |
| 角色已知 | 实际读到或听到什么、来源与时间 | 现有阅读档案、知情事实与场景记忆 |
| 功能状态 | 实际安装在哪里、是否启用、当前有何具体影响 | 现有设备与义体状态；需要时只补相应芯片定义 |

同一内容允许有不同副本；载体归属与内容身份分别引用。同名资料可能不是同一份，同一份资料的部分解锁也不能被当成毫无关联的新物件。

## 五、原文、说法与知情边界

- 原文一旦呈现即固定。芯片可以记错、撒谎、留有缺页或被剪辑，先记录它写了什么，再依据实际证据判断真假。
- 玩家推断、文件说法与已查明世界事实分开保存，不把读取等同于证实。
- 加密或尚未读到的部分不进入角色知识；已取得载体、已经读过、界面有没有点开，使用不同含义。
- 给别人看、发去副本或当面转述以后，才按实际到达的信息更新对方；其他熟人不会同步得知。
- 普通个人记录与成人作品按实际来源和分享范围处理；持有不自动意味着录制、传播或任意读取其他人的设备。
- 未知芯片的风险来自具体来源、防护或实际异常，不默认每次插入都受伤、被追踪或出现新任务。

调查同样通过正文主动追问与既有黑客规则承接：能读取什么受材料与设备约束，已经解出的内容保持稳定，不新增破译小游戏或线索评分。

## 六、现有实现中必须补齐的部分

当前 `packages/core/src/systems/shards/` 保存的是已经读到的原文，还不能单独承接完整的载体使用流程：

1. `schema.ts` 的 `read=false` 表示玩家尚未点开阅读面板，不表示角色还没读过。保留清楚的语义，不能据此把未知内容当已知。
2. `apply.ts` 当前按标题和全文去重，需要改为稳定内容关联，才能区分不同载体与同一内容的部分读取。
3. 当前超过 60 条直接删除最早资料。改成持续保存、按需分页或归档；数量增加不能抹去重要原文与物件来源。
4. `prompt.ts` 当前只带最近 8 条。改为按当前人物、地点、作品与玩家引用召回相关原文，不能让较早资料失去使用价值，也不把全库常驻上下文。
5. 原文较长时可按内容分段展示与召回，不能因单条展示限长悄悄截掉后续关键信息。

以上围绕资料关联与可靠保存完成，不扩成文件管理器、磁盘空间经营、权限图或通用软件平台。实际正文质量、角色口吻与描写继续遵循写作预设。

## 七、实施顺序与验收

1. 打通内容稳定 ID 与现有物品、载体的关联，区分获得、读取和界面已读；修正原文保存和相关召回。
2. 把正文读取、实际复制、赠送、借用与交付接到现有物品、交易和记忆；解密仅在有实际条件时调用既有黑客流程。
3. 补少量生活媒体、教程、私人记录与具体功能芯片；行为用途接玩偶策划，超梦内容接超梦策划，不重复造系统。

主要接入：`packages/core/src/systems/` 下的 `inventory`、`shards`、`commerce`、`hacking`、`cyberware`、`npc`、`memory`，以及 `packages/content/src/` 中的实际物件与内容资料。保持现有正文与阅读入口，不借机重做界面布局。

制作阶段不保留旧格式兼容层。每步执行 Git，有改动立即单独提交；不主动运行单元、集成或浏览器测试，仅保留必要静态检查，实际体验交给用户。

- [ ] 拿到未读或加密芯片时，不会自动获知其中尚不可读的内容。
- [ ] 重读、重试与读档后的原文一致，同名不同资料不会错误合并。
- [ ] 交出原件后归属正确，已经读过的知识仍可引用；实际副本有来源，不凭空复制。
- [ ] 较早资料不会因后来新增内容被删除，并能在有关场景中召回原文。
- [ ] 给某个人看过什么有依据，资料说法与玩家推断不自动成为世界真相。
- [ ] 普通买片、留教程和赠送合集能平静结束；辅助与行为芯片有真实用途且不越过设备和玩家控制边界。
