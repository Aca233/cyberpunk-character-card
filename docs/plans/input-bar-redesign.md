# 剧情主界面输入框（InputBar）视觉与交互优化方案

状态：已完成（2026-11-22，按用户确认全套落地，仅调整剧情主界面输入框，手机私信框保持现状）

## 一、现状诊断

当前主剧情输入框位于 `apps/web/src/features/story/InputBar.tsx`，样式位于 `apps/web/src/features/story/story.module.css`（`.dock`、`.inputBar`、`.textarea`、`.replyChip`）。对照全站赛博朋克 2077 原作 HUD 风格与文字 RPG 高频输入场景，存在以下明显短板：

### 1. 视觉与布局问题
- **风格割裂，方框感强**：全站选项条 `.choice`、按钮 `Button`、通知 `.toast` 与其他输入框（`FrameBox` / 手机短讯 `Phone.tsx`）都采用了赛博斜切角或原作九宫格框线，唯独主界面 `.textarea` 是普通直角矩形（`border: 1px solid` + 聚焦 `inset box-shadow`），显得像默认网页表单。
- **多行输入时发送按钮被强行拉高**：`.inputRow` 使用 `align-items: stretch`，旁边独立摆放一个 `Button`（使用 `NineSlice tab.bg`）。玩家输入 3–6 行长文本时，右侧按钮会跟着拉伸到最高 `10rem`，比例失调。
- **字数计数遮挡正文**：`.charCount` 使用 `position: absolute; right: 0.55rem; bottom: 0.3rem;`，而 `.textarea` 未预留底部空间，字数接近上限时会直接压在最后一行输入文字上。
- **回复引用条游离在外**：`.replyChip` 独立悬在输入框上方，仅有一条暗黄左边框与文字，与输入框缺乏一体感。
- **`.dock` 滚动冲突挤掉输入框**：`.dock` 整体设置了 `max-height: 296px`（`< 1600px` 屏幕仅 `232px`）且 `overflow-y: auto`。当剧情选项达到 4–5 条或输入框写多行时，整个底部区域一起滚，输入框和 `KeyBar` 容易被挤出可视区。

### 2. 交互与好用度痛点
- **键盘流断裂（无快捷聚焦，且 `Esc` 被困在输入框内）**：`StoryScreen.tsx` 中 `isTyping(e.target)` 拦截了所有按键，导致焦点在输入框内按 `Esc` 毫无反应，无法一键退回 `1-5` 选选项或 `P/O/J/T/M` 开面板；反之，在阅读态也无法用快捷键（如 `/`）直接聚焦开写。
- **长段 RP 编辑局促**：最大高度仅 `10rem` 且受 `.dock` 总高度挤压，写几百字描写与对白时视野窄；同时缺少「清空草稿」按钮（从装备/扫描/人物档案注入草稿后想放弃需手动全选删除）。
- **不支持发送键位偏好**：目前固定 `Enter` 发送、`Shift+Enter` 换行，对习惯用 `Enter` 分段写长 RP 的玩家容易误发送。
- **装了斯安威斯坦却无法在输入栏主动切换**：`TurnInput` 与后端 `turn.ts`、前端 `store.ts` 均已完整支持 `sandevistan: true` 与对应音效/特效，但自由输入时玩家无法直接点亮开关，只能靠写关键词让判定模型猜测。
- **草稿无持久化、无法调回上一句**：刷新页面会丢失正在写的长草稿；空框时也不能按 `↑` 快速取回上一轮输入微调。
- **状态反馈单薄**：推演中预输入下一轮、回复消息、超字数、死亡/结局封存等状态差异太弱，尤其死亡/结局后仍占着一大块灰色输入框。

## 二、优化方案

### 1. 视觉升级：一体化赛博命令终端（Composer Shell）

将原本“独立文本框 + 右侧拉伸按钮”重构为一个统一的赛博终端输入容器：

- **容器造型**：
  - 使用暖暗深底（`--cp-surface-strong` / `--cp-surface-inset`）、赛博斜切角（如右下角切角 `clip-path` 或原作框线语言）、左侧 2–3px 状态色柱与顶部极细高光线，与上方 `.choice` 选项条和下方 `KeyBar` 形成统一视觉节奏。
  - 聚焦时整体容器切换状态色（边框、柔和内发光与底栏响应），而非给 `<textarea>` 套生硬内阴影。
- **内部纵向三段式（按需展示）**：
  1. **顶部附属条（条件显示）**：将回复短讯 `replyChip` 收纳为终端顶部内嵌横幅（标记发信人、单行预览、紧凑 `×` 取消键），归属感强。
  2. **中部编辑区**：无边框纯净 `textarea`，默认紧凑起步（约 1–2 行，节省阅读空间），随输入内容平滑增高。
  3. **底部内联控制栏（Action Bar）**：高度恒定，彻底解决多行输入拉歪按钮的问题。
     - **左侧**：状态指示点/短标（待机 / 推演中可预写 / 斯安威斯坦激活）+ 可选芯片开关（如斯安威斯坦、发送键位切换）。
     - **右侧**：字数统计（放入底栏永不遮字）+ 轻量「清空」按钮（有文字时出现）+「展开/收起」编辑高度切换 + 紧凑发送按钮 / 红色「停止生成」按钮。
- **六种状态语义明确**：
  - **待机态**：暗红框线 + 暖暗底，存在感克制，不抢正文注意力。
  - **聚焦态**：青色或模式高亮框线 + 微弱柔光。
  - **推演中（可预输入）**：顶部细微青色流光条（`prefers-reduced-motion` 下静态）+ 左侧「推演中 · 可预写下一步」提示 + 右侧「停止生成」按钮。推演结束后**不自动盲发**（防止上一轮突发剧情导致误操作），而是即时高亮「发送」按钮，确认后一键发出。
  - **斯安威斯坦开启态**：状态色切为标志性赛博金黄，边框与芯片开关同步亮起。
  - **超字数态**：边框与底栏计数切为 `--cp-danger`，禁用发送并在底栏提示精简字数。
  - **死亡 / 结局封存态**：收起为一行紧凑只读提示条，把底部空间还给剧情回看。
- **解除 `.dock` 滚动冲突**：
  - 拆分 `.dock` 内结构：让 `.choices` 独立受控滚动，确保 `InputBar` 与 `KeyBar` 始终稳固停靠在底部，不再被选项挤出视口。

### 2. 交互升级：更顺手的键盘流与长文体验

- **键盘闭环**：
  - 阅读/HUD 态按 `/` 一键聚焦输入框并把光标放到末尾。
  - 输入框聚焦时按 `Esc`：若处于展开态则先收起；否则 `blur()` 失焦回到剧情快捷键模式，方便立刻按 `1-5` 或 `P/O/J/T/M`。
  - 输入框为空时按 `↑` 调回本存档上一条玩家自己发出的文本，便于修改重发。
- **发送键位偏好**：
  - 底栏提供紧凑切换（`Enter 发送` / `Ctrl+Enter 发送`，持久化到 `localStorage`）；无论哪种模式，`Ctrl+Enter` / `Cmd+Enter` 始终可直接发送。
- **长文展开模式**：
  - 点击底栏展开图标（或快捷键 `Alt+E`）将输入区平滑扩高至舒适写作高度（如 `14rem`），发送成功后自动收起。
- **斯安威斯坦快捷开关**：
  - 仅在 `view.sandevistan !== null`（已装且未损坏）时显示紧凑芯片开关，直接绑定 `draft.sandevistan`，发送成功后自动复位。
- **按存档持久化草稿**：
  - 将未发送的 `draft.text` 按 `saveId` 轻量同步到 `localStorage`（仅在变更时写入，发送成功后清除），刷新页面或切换路由不丢长草稿。
- **有字时一键清空**：
  - 草稿非空时显示低干扰「清空」图标/按钮，方便撤销从装备/扫描注入的行动文本。

## 三、实施记录与改动范围

- `apps/web/src/features/story/store.ts`：新增按 `saveId` 持久化草稿（`cp.storyDraft:${saveId}`），统一清理可选字段与 `sandevistan` 复位逻辑。
- `apps/web/src/features/story/InputBar.tsx`：重构为一体化赛博命令终端壳体（双层斜切角、顶部内嵌回复横幅、纯净自适应编辑区、恒定高度内联底栏），补全发送键位切换（`Enter` / `Ctrl+Enter`）、长文展开（`Alt+E`）、清空、`Esc` 失焦、空框 `↑` 调回上一轮输入、斯安威斯坦芯片开关与封存单行态。
- `apps/web/src/features/story/StoryScreen.tsx`：新增 `/` 一键聚焦输入框快捷键，透传 `view.sandevistan` 与本存档最近一条玩家输入 `lastSentText`。
- `apps/web/src/features/story/story.module.css`：将滚动隔离至 `.choices`，重写 `.inputBar` 六态样式与降动效适配，清理旧 `.replyChip`。
- `apps/web/src/features/story/Phone.tsx`：按用户确认保持现状。
- 静态检查：`npx biome check` 与 `npx tsc --noEmit -p apps/web/tsconfig.json` 均通过（按项目约定交由用户实机测试验收）。

不涉及后端接口改动、不改动提示词逻辑、不改动两侧 HUD 角块与展开面板布局。
