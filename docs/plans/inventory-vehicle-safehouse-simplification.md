# 物品、车辆与住所收敛设计方案

状态：**草案待确认**（审计已完成，暂未修改业务代码与界面布局）  
日期：2026-11-18

## 一、核心诊断与方向评估

方向判断完全正确：当前问题不是“缺少存放箱 UI”，而是后台数据、指令校验与状态注入把“世界因果可信”做成了**玩家/模型必须配合容器手续与人工门槛**。

结合代码现状，实际存在三层错位：
1. **界面与后台已出现“虚实脱节”**：前端（`apps/web/src/features/story/`）实际上**根本没有**存放箱或后备箱操作面板；只有 `StoryScreen.tsx` 买房确认文案中还残留“存放箱”字样，而后端仍保留了 `StashActionSchema`、`safehouseInteractions`、`PlayerView.safehouse.homes[].items` / `trunks` 等冗余面板接口。
2. **后台人为门槛反而阻碍了自然故事**：`applyVehicle` 的 `abandon` 强制要求人在车旁且后备箱为空（`后备箱还有物品，先取空再弃车`），且弃车后直接 `splice` 删除车辆；`applyStash` 要求先 `item unequip` 再存入、要求结算瞬间的 `world.location` 必须对上容器位置；普通目录物品若不在安全屋或后备箱而是留在某处场景/交由他人看管，`applyItem` 缺少通用“留置位置”记录。
3. **状态注入过宽导致正文与 Token 失焦**：当前并没有为整理物品单独发 LLM 调用（所有 `item` / `stash` / `vehicle` 变化都已在 `④ Extract` 一轮内完成），真正耗费 token 并把注意力拉向资产盘点的是 `【当前状态】` 的无条件全量平铺——`safehouseStatus` 每轮列出所有已拥有住所及全部屋内物品，`travelStatus` 每轮列出名下全部车辆及停放点，且 `travelRules.narrate` / `physicsSection` 还会暗示正文提及车况、后备箱和存放动作。

## 二、五条原则的对照与落地设计

### 原则 1：普通生活动作合并处理
> “回家拿枪，换件衣服，然后出门”就是一次完整行动。后台一起更新，不要求打开箱子、逐件取出、装备、确认。

- **现状卡点**：
  - `prompts/extract.ts` 规定每轮通常只落最终 `world` 地点；`applyStash`（`packages/core/src/systems/safehouse/apply.ts`）按命令执行时的 `world.location` 校验是否在场，导致“先回家拿枪换衣再出门”要么因最终地点不在家而失败，要么拆成两次 `world` 移动重复触发 `autoMove` 扣时扣钱。
  - 穿着中的 `clothing` 或快捷栏 `healing`/`grenade` 必须先发 `item unequip` 才能存入，不能一步“脱下并留在家里”。
  - `StashCommandSchema` 没有 `count` 字段，多件同类物品要写多条指令；`safehouseRules` / `travelRules` 依赖较死板的正则关键词触发。
- **建议方案**：
  - 在**同一轮结算内**支持“途经住处/车旁顺手取放换装后再出发”的合并处理：把“在安全屋/车内换装、取枪、留置物品”作为可携带**明确途经地点（或动作内嵌容器位置）**的同步状态变更，不额外触发 `autoMove` 路费，也不强制按两段行程拆轮。
  - 若留下的物品当前正穿在身上（`clothing`）或占着快捷栏（`healing`/`grenade`），结算时**自动解除穿戴/装备并完成留置**，不报错阻断。
  - 允许单条指令带 `count`（缺省为 `1`），放宽规则触发条件，避免因玩家措辞口语化（如“回窝带上家伙就走”）漏加载规则。

### 原则 2：只有明确留下的东西才需要额外记录位置
> 随身装备按原物品栏使用；玩家明确把枪留在家、把尸体藏进车里、把证据交给某人，才形成需要持续记住的事实。不要主动给每件杂物安排复杂的存放关系。

- **现状卡点**：
  - 目前状态分裂成三套：`safehouse.stash`（安全屋 id → 物品 id → 数量）、`travel.vehicles[].cargo`（车辆 cargo → 物品 id → 数量）、以及 `inventory.objects`（仅覆盖自定义 `WorldObject`，其中 `holder: "stash"` 甚至丢失了具体放在哪间屋或哪辆车）。
  - 普通目录武器/物品（`data.items`）如果被玩家明确留在非安全屋/非后备箱的场景（如酒吧柜台、某 NPC 处），`applyItem("lose")` 若没有对应 `recipient` 或 `WorldObject` 定义，会直接从 `backpack` 删除，后续剧情无法再追回或追溯。
- **建议方案**：
  - **随身**：继续沿用原 `inventory`（`backpack` / `clothing` / `healing` / `grenade` / 随身 `WorldObject`），不改玩家对随身物品栏的认知。
  - **非随身（明确留下的东西）**：不再以“存放箱/后备箱格子”为核心心智，而是统一收敛为**“明确留置/托管事实”**：
    - 玩家明确放下、留在家中、放进车内、藏在某处或交给某人的关键物品/物件，记录一条带归属位置（安全屋 / 车辆 / 场景地点 / NPC + 简短备注与时间）的留置记录；
    - 一般消耗品、未刻意强调的杂物不主动建档或强行分箱；
    - 提取提示词明确约束：只在玩家**显式交出、放下、藏匿或留下**某物，或剧情明确使其脱离随身时才写留置记录；日常拿在手里的装备保持在原物品栏中。

### 原则 3：位置只在产生后果时进入正文
> 车停在哪，不必每轮强调；玩家准备开车、车辆被偷、逃跑路线受影响时，它才重要。物品也一样：平时安静记录，需要使用却不在身边时，才自然体现。

- **现状卡点**：
  - `safehouseStatus`（`packages/core/src/systems/safehouse/status.ts`）每轮把名下所有住所和“屋内物品”（哪怕为“无”）全部写入 `【当前状态】`。
  - `travelStatus`（`packages/core/src/systems/travel/status.ts`）每轮把名下所有车辆和停放位置写入 `【当前状态】`。
  - `travelRules.narrate` 和 `physicsSection` 会主动诱导正文写车况、后备箱和存放行为。
- **建议方案（区分“裁判/提取准确性”与“正文注意力”）**：
  - **正文生成（Narrate）降噪**：
    - 只有满足以下任一条件时，才把住所/车辆/留置物品的详情注入正文上下文：
      1. 位于玩家**当前地点**（人在家、车就在身边、物品留在当前场景）；
      2. **本轮行动涉及**（玩家要开车、要回家、要拿/找某件不在身上的东西、或正处于载具/追逐场景）；
      3. **正在产生后果**（车被偷/被拖走/受损报废、留下的证据或尸体引发追踪、住处被盯梢或闯入）。
    - 删掉鼓励每轮顺口提及停车点、后备箱内容或广告买房的提示词诱导。
  - **裁决与防幻觉（Judge / Extract）的最小兜底**：
    - 当玩家在行动中尝试使用/掏出某件物品或开走某辆车，但它不在身边时，`Judge` 仍需知道“东西不在身上，而在 X 处”或“车停在 Y 处”，才能自然裁决“伸手一摸发现枪留在公寓了”而不是凭空变出来。
    - 实现上可在 `Judge` / `Extract` 使用轻量按需索引（优先基于随身清单 + 仅当玩家意图涉及出行/取物/某件留置物品名称时附带对应留置位置与车辆位置，或极短的单行缺失映射），避免每轮把全量资产清单塞进 `Narrate` 上下文。

### 原则 4：减少人为门槛，允许玩家承担后果
> 例如车里有物品，不应该因此禁止弃车。玩家完全可以连车带物留下；涉及重要证据时提醒一句，留下之后世界继续演变。限制应来自实际处境。

- **现状卡点**：
  - `packages/core/src/systems/travel/vehicles.ts` 的 `applyVehicle("abandon")` 规定：`target.location !== here` 不许弃车；`Object.keys(target.cargo).length > 0` 不许弃车（`后备箱还有物品，先取空再弃车`）；成功弃车时 `draft.vehicles.splice(...)` 直接抹除记录，没有后续世界后果。
  - `travelRules` 重复强调“有后备箱物品时不能弃车”。
- **建议方案**：
  - **取消人工禁令**：移除 `abandon` 的“必须人在车旁”和“必须取空物品”校验，允许玩家随时随地连车带物弃车（例如徒步逃离现场、把着火或惹上条子的车甩在原地）。
  - **高风险留置的自然提醒**：当玩家准备抛下车辆或离开现场，而车内/现场留有重要证据、关键任务物件或尸体等高后果物品时，在 `Judge` / 正文中给出自然且不强制阻断的提醒或当下直觉反馈（由玩家自己决定回头拿还是直接丢下）。
  - **留下的东西继续在世界里演变**：弃车不再静默删除事实，而是转为“无主/遗弃车辆（附带车内留置物品与地点）”，进入后续 `offscreen` / 世界演化视野——可能被偷、被 NCPD 拖走顺藤摸瓜查到车主或指纹、被帮派搜刮，或在无人问津时还能回去找回。
  - **只保留物理与处境限制**：人在城北、车停城南时不能“直接踩油门开走这辆车”；车报废了开不动；不在现场时不能隔空伸手从车里掏东西——这些都是物理事实，而非规则门禁。

### 原则 5：房屋和车辆的价值来自故事中的用途
> 房屋可以休息、接待朋友、藏人、被监视或遭到闯入；车辆可以出行、接人、逃跑、运输、留下行踪。这些用途由当前故事触发，不必分别制作一套管理系统。

- **现状卡点**：
  - 目前房屋系统主要围绕 `buyHome`（限制只能在 UI 购买，提示词还明文禁止故事里送房/买房）和 `stash` 展开，故事向事件（被盯梢、遭闯入、藏人、朋友来访）缺少轻量状态钩子。
  - 车辆系统已有 `stolen`、`condition`（`intact`/`damaged`/`wrecked`）、追逐 `chase` 和偷车 `steal`，方向最接近，只需去掉多余后备箱管教并强化“留下行踪/热车风险/载具运输”的故事触发。
- **建议方案**：
  - 不做房租、家具、装修、保养、油量、停车费等管理系统。
  - 住所与车辆只保留故事真正用到的少数字段：
    - **住所**：身份归属、地点、安全状态/异常标记（如“被盯梢”“暴露/被搜查过”“暂留某人”），由剧情与 `offscreen` 触发休息、接头、藏身或危机。开放故事中自然获得/借住/失去住处的路径（不必死卡在商店购买按钮）。
    - **车辆**：车型（图鉴与外观）、名称、当前位置、状态异常（`stolen` / `damaged` / `wrecked` / 可选的遗弃或通缉关联），继续服务于出行、接人、逃跑、运货与留下行踪。

## 三、界面收敛方案（待确认后统一改动）

对照现状代码（`apps/web/src/features/story/`）：
1. **原物品栏保持原样**：`InventoryPage`（`NeuralPages.tsx`）的分类、搜索、穿戴/卸下、配件改装、吃药/使用交互保留不动；仅清理 `StoryScreen.tsx` 等处提到“存放箱”的过时文案与注释。
2. **取消专门存放箱与后备箱操作接口**：
   - 删除后端 `StashActionSchema`（`safehouse/actions.ts` & `actions.ts`）、无调用方的 `safehouseInteractions`（`safehouse/interactions.ts`）、`PlayerView.safehouse.homes[].items` / `trunks`（`safehouse/view.ts`），以及未使用的 `OutfitActionSchema`（若确认不重启衣柜管理面板）。
3. **车辆只在主动展开时提供图片、名称、位置和异常情况**：
   - `VehiclesPage.tsx` 本身已经接近目标（仅展示图片、名称、位置、赃车/受损/报废标签，外加一个跳地图按钮）。
   - 需要收敛的两处细节：
     - **避免悬停被动弹出**：右下角 `Weapon` 块使用 `usePeek("weapon", ...)`（悬停 90ms 即自动展开），且会记住上次选中的 `gearTab`（`inventory` | `vehicles`）。若要严格符合“只在主动展开时提供”，建议收起后重置回物品页签，或将车辆列表改为仅在点击/按键钉住展开并切到车辆页签时展示（不随 90ms 悬停直接把车辆表带出来）。
     - **确认 `VehiclesPage` 是否保留“地图”定位按钮**：若希望车辆页纯粹只做只读查看（图片、名称、位置、异常），可评估去掉“地图”跳转按钮或仅作辅助保留。

## 四、调用与 Token 策略

- **LLM 调用次数**：继续保持 **0 额外调用**。所有物品带走/留下、换装、车辆状态变化与异常标记，都在现有回合的 `④ Extract` 与本地确定性结算中顺带完成；不增设整理物品或存取确认专用调用。
- **上下文 Token 降噪**：
  - 取消 `safehouseStatus` 和 `travelStatus` 的全量列表输出；
  - `placeSections` / `inventoryStatus` 保持随身必需信息，远方住处、远方车辆与留置物品按“**在场 / 本轮提及或意图相关 / 处于异常或待兑现后果**”过滤后进入上下文。

## 五、待用户拍板的 4 个设计细节

在动手修改代码与界面前，先确认以下四项即可直接锁定实现边界：

1. **后端存放数据结构是否一步重构为统一“留置/遗弃记录”？**
   - 按“制作阶段不做历史兼容”约定，建议直接废除 `safehouse.stash` 与 `vehicle.cargo` 两套物品计数表，统一收敛为轻量的留置记录（既覆盖放在家里、塞进车里，也覆盖“把枪留在酒吧”“把证据交给某人”“连车带物抛在原地”）。
2. **重要证据/关键物品弃车时的“提醒一句”落在哪一层？**
   - 选项 A：仅在**正文/叙事反馈**中自然点出“后座还塞着那箱证物，但你没有停步”（完全不打断输入，留给玩家下一轮决定是否折返）；
   - 选项 B：类似大额消费确认，遇到高风险关键物件即将脱离身边时给一次轻量行内提示，但**依然允许一键直接继续承担后果**。
   - （推荐选项 A，最贴合“少人为门槛、直接承接后果”与正文沉浸感。）
3. **右下角车辆查看的“主动展开”交互边界**：
   - 收起物品块时默认切回“随身物品”，只有玩家主动点击/按快捷键展开并切到“车辆”页签时才显示车辆列表；`VehiclesPage` 里的“地图”定位按钮保留还是去掉？
4. **“安全屋购买入口”和“人物服装快捷切换 (`outfit`)”去留**：
   - `InventoryPage` 底部当前还会显示当前地点的“待售公寓”购买按钮；是否保留该便捷入口，同时解除“禁止在故事中获得/失去住处”的提示词限制？未接前端的 `OutfitActionSchema` 是否一并清理？
