# 因果事件结算 · 2026-11-17

## 目标与边界

让状态变化明确属于某件事，并记录它依赖哪件事成功。失败只撤销本事件、阻止依赖它的后续事件，独立事件仍可生效。沿用现有界面和写作预设，正常回合仍使用原有判断、正文与抽取调用。

本轮不扩展车辆位置、物品实例或全城自治。制作阶段直接切换抽取协议，不保留没有事件清单的旧格式结算路径。

## 抽取协议

`changes`、`messages` 保持各自业务字段，新增必填 `events`：

```json
{
  "changes": [
    { "type": "breach", "network": "保险柜内网", "via": "接入点", "gains": ["data"] },
    { "type": "loot", "amount": "some", "tier": "street", "reason": "保险柜转账" },
    { "type": "loot", "amount": "some", "tier": "street", "reason": "朋友归还旧债" }
  ],
  "events": [
    { "id": "access", "requires": ["$action"], "entries": ["changes[0]"] },
    { "id": "vault-transfer", "requires": ["access"], "entries": ["changes[1]"] },
    { "id": "friend-repayment", "requires": [], "entries": ["changes[2]"] }
  ]
}
```

每条变化和消息必须恰好归属一件事。同一事件是不可拆开的事务；它的全部指令及内部连锁一起提交或撤销。依赖只能引用前面的事件或 `$action`，禁止悬空引用、重复归属、自依赖、循环及乱序重排。无变化时明确给空清单。

`$action` 表示本轮玩家主行动的成功前提，已有判断为 `blocked` 时不成立；直接取得的行动收益也必须声明它，不允许通过省掉入侵指令绕过。尝试失败后的真实受伤、报警和已经付出的成本不以成功为前提。独立收入可以独立发生。

## 执行与恢复

1. 先校验事件清单，再按现有有界修复流程核对业务字段。坏图不能靠代码猜依赖，保存零结算草稿。
2. 按声明顺序执行，一事件只试算一次。首条失败即停止本组，撤销本组状态、补丁、成功通知和购买授权消费。
3. 交易授权在全轮共享，只能成功消费一次；交易的重复记账判断限于相关事件，避免误伤独立的同额收入或同款赠品。
4. 删除按整轮“付钱/拿货/开战”类别猜因果及反复重算机制。代码产生的出行、回复、义体启动等同样进入事件结算；主行动后果受相应前置动作约束。收场不能越过失败事件。
5. 部分成功标记为未完整结算，不标成零结算草稿。保留成功事件账目，继续使用已有“按账目改写”；不采纳矛盾正文的整场记忆或幕后推演。完全没有事件落地时可保留零结算草稿重新生成。

## 验收重点

- 失败接入阻止取款和后续消息，独立还款仍到账；省略接入指令也不能绕过 `$action`。
- 组内先付款后交货失败时一起撤销；独立付款、物品、伤害不互相误杀。
- 授权不能跨组重复消费，失败事务不占用授权。
- 交易移动产生的内部出行费用、时间与通知随所属事件一并回滚。
- 坏引用、重复编号、缺少归属、修复失败不会绕过结算；成功事件不重复执行或重复抽随机数。
- 部分结算不污染记忆、不会被草稿恢复逻辑重复发奖；保存、载入和按账目改写维持一致。

## 实际能力限制

此机制核验明确声明的依赖和已有世界规则，不能证明模型对自然语言的所有理解正确。将相关收益错误声明为独立事件仍属于抽取质量问题；当前也只有一份主行动裁决，尚不是多目标、多动作各自裁决系统。后续应基于真实失败案例逐步补齐，不能声称已实现任意行动的完美因果模拟。

## 本批实现与验证

以上协议和事件结算已接入正常游戏回合。原来的整轮类别联动、失败入侵与任意收益一起退回的临时保护、从初始世界反复重算均已移除。每个事件只执行一次，失败前已经消费的随机值不回卷；成功事件不会因其他事件失败而重新抽样。

抽取格式缺失仍复用原有有界格式修复；事件归属或依赖图错误直接保留零结算草稿，不调用模型猜依赖。部分成功使用现有未完整结算与按账目改写入口，保存实际状态；错误正文不进入后续历史、记忆、摘要或幕后推演，也不派生选项与危机标记。首轮部分结算后不会误触发重复开场。
