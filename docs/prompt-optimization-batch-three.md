# 提示词优化第三批交付记录

日期：2026-11-16。基线 `7c68022`。正文质量优先，文笔交给启用的预设，原界面保持原样。

## 已实施

1. **正文与记账异常可以恢复。** 正文中途断流、达到输出上限，或整份抽取失败时，将已经收到的正文保存为未结算草稿；本轮不提交状态、移动、记忆或场外变化。没有收到正文时仍返回原始请求错误，玩家主动停止仍终止回合。草稿不进入下一轮事实上下文，不能通过“按账目改写”变成正式事实，需使用重新生成。已完整结算的正文不因后续摘要或场外请求中断而丢失。
2. **纠正摘要同时清理其派生记忆。** 修改摘要正文或删除摘要，会使该场景的旧提要、锚点、待整理记忆和纠正时点之前的原文退出模型记忆；原始日志保留。仅改标题或重要性不触发失效。同场后续新事实与其他场景记忆继续可用；若被纠正的场景曾结清更早的承诺，该承诺重新打开。当前来源粒度为场景，纠正摘要不会倒改物品账本或世界状态。NPC 独立保存的共同记忆目前没有场景来源字段，因此不会随场景摘要一起更正；已进入该处的错误仍可能回流，不能宣称所有来源都已同步纠正。
3. **关系、扫描与知情范围分开。** 见过面、扫描过或有仇，不再自动等同深交或解锁秘密。人物依照实际获知信息及来源回应；知道某人的存在，不等于知道远处刚发生的死讯。隐藏秘密作为幕后设定提供，透露须有具体来源、目的与边界；这仍依赖模型遵守提示，不是完整知识图谱。
4. **场外积压按辅助模型容量分批。** 使用实际辅助连接的上下文窗口和输出上限估算容量，按完整回合从早到晚处理。部分批次只推进成功游标，不重复推进自主生活、不触发约定提醒；全部补齐后才更新完整成功时点。必要上下文或单轮材料就已超限时不发请求、不推进游标，并记录原因。估算不等于模型真实分词，保留了协议余量。
5. **文笔由预设负责。** 启用预设时不再发送默认文风、好坏示例、修辞重复提醒或动态篇幅节奏指导；系统模块也移除统一短句、冷峻语气和感官细节配额。保留事实、权限、角色身份与知情边界。人物自身的口吻、经历和样本继续存在，预设不改写其身份。未启用预设才添加默认表达层，未修改用户预设。
6. **记忆区分说法与事实。** 增加未核实说法 `report`，玩家意图或自述不能单独证明事实发生或承诺兑现。关键物品、欧元声明可附结构化 `settlement`，对照主线结算前后的净变化验证，避免把场外变化误当本轮证据。没有声明结构化结算的自然语言仍无法自动证明正确，引用匹配也只证明引文存在。
7. **清掉后果素材中的跑团残留。** 删除好感扣点、难度加值、星级驱动后果和检定措辞，替换为已知事实、实际损失、人物获知信息与具体因果。内容检查增加后果和局面素材，避免这类文本绕过已有规则检查。

正常主链仍是判断、正文、抽取三次调用。故障恢复与本地证据校验没有增加每轮固定模型调用；摘要质量恢复、场外推演与有限格式修复仍按需要调用。没有使用关键词跳过必要判断。

## 真实样本与限制

使用当前连接与启用预设完成三次真实正文请求，判断、抽取模拟，未调用评分模型、未重试、未写真实存档或配置。本次观察中：扫描与仇怨未泄露秘密；缺少来源的人物不知道远处死讯；公司人物维持礼貌完整句式，没有替玩家签字或承诺。三次均自然结束。

三个样本分别为 1,055、1,176、1,580 字，存在较多雨景、霓虹和微动作铺陈。样本生成在最终预设职责拆分之前；最终调整以请求结构与回归测试验证，没有再次调用模型。它不是 A/B 对照，也不证明整体文笔、长线记忆或所有人物表现已经提高。

服务端报告合计输入 51,993、输出 10,777 tokens。请求输出上限各为 1,800，但返回用量高于此值，无法由本次响应区分额外推理计数或上游未严格执行上限，不能据请求参数保证实际费用。原始报告和正文保存在 `.run/prompt-batch-three-20261116/`，不进入玩家存档。
