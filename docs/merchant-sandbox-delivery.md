# 商店与义体服务三批交付

日期：2026-11-17。状态：三个批次已完成并通过验收。实施基线：`4c37567`；最终代码验证提交：`e26491b`。对应策划：[merchant-sandbox-plan.md](merchant-sandbox-plan.md)。

## 第一批：同一份报价与实际成交

- 普通店铺、人物私人交易和义体服务共用各自的报价函数，原按钮、自由输入、大额消费确认和最终扣款都读取同一结果。
- 交易必须明确对方。人在某家店里，不会自动把与另一个人的交易算到店铺库存上。人物出售物品使用实际持有物，不能凭目录制造货物。
- 询价、砍价与交付分开。已接受报价记录对方、具体物件、价格、替换对象、实物、旧件去向、来源引文和约定期限；没有约定有效期就不强加倒计时。已用、撤回或过期报价不能再次使用。
- 多件交易按明确授权顺序逐件核对，临时预览连续计算余额和库存，合计支出触发大额确认。服务端将确认绑定到本轮输入、存档版本和具体报价；改变商品、价格或条款需要重新确认。
- 一次授权只能成功成交一次。拒绝同轮重复交易、重复给货和重复扣交易款；卖出武器保留实际配件。单笔连锁失败回滚，不留半笔账。
- 先去商店再购物按实际顺序结算到达、路费和交易；连续去两家店不会把后一次移动挪到第一次成交之前。正文可见所需路费、耗时和抵达时刻。

## 第二批：持久商家与地图入口

- 内容表接入 **102 家普通商家、20 家义体诊所，共 122 个经营身份**。涵盖武器、近战武器、服装、药品、食品、酒吧和义体诊所；未支持的地图服务类别仍然只是地点。
- 已核对的剧情地点和地图 POI 指向同一家店，共享经营状态与库存。Wilson 与 H10 枪店、Viktor 与相应诊所入口明确关联；同名但不同地址的店不合并，虚构商家不硬套原作 POI。
- 首次访问、有关订单或经营事实激活详细状态，之后保存。重访和载入不重新生成现货，也不会过三天自动补满。首批货架与供货关系是本作初始设定，不宣称是原作逐项库存。
- 判断上下文只提供现场、相关附近或玩家明确提及的经营身份、地点和服务，解决地图新店有名字但模型不知道交易 ID 的问题。同名地点保留各自 ID 以便消歧，不向每轮请求塞入全城货架。
- 明确死亡或离场的店主、医生不能继续亲自服务；登记过的在场代班人员可提供服务。位置未知不会被当成已经离场。诊所普通医疗服务也核对实际经营状态。
- 删除废弃声望解锁数据，不增加等级、声望或人性门槛。

## 第三批：供货、实物与服务阶段

### 供货和经营

- 普通商店按已保存的供货方、来源、路线、货物、数量和运输时间建立订单。没有供货关系就不会自动补货。购买导致缺货时只补实际缺口，不复制售回的独立实物。
- 玩家可在卖方已同意的前提下订货、取消和到货后取货；当前采用到货付款，不收虚构订金。诊所支持有来源、路线和到达时刻的义体供货单。
- 本地游戏时间推进运输。相关路线封锁时暂停剩余运输，解封后继续；到货只执行一次。剧情入口与同店 POI 的封锁影响同一条供货路线。
- 场外推演复用已有请求，增加限定的营业、人员/设备与路况变化；每条必须引用已有或本批城市事件的明确证据，并且只影响已激活商家或相关路线。场外不能替玩家付款、买卖、预约、开始或完成手术。

### 义体实物和手术

- 购买未安装义体会生成独立实物身份，记录型号、持有人、位置、货况、来源。自带件只付服务费用，已售罄诊所不会因为安装自带件凭空添库存。
- 未安装实物使用原背包和详情字段展示，可通过原存放操作存入安全屋或后备箱再取出；场景记忆可以验证这类实物确实交付。没有新建前端面板。
- 替换和拆卸必须有具体目标及旧件去向。保留会留下实物，明确出售才给回收款，明确报废才废弃；不会自动删除最早安装的义体。
- 简单手术可一次完成，使用共同报价中的开始、结束时刻推进时间。正文已走到结束时刻时，不再次累计耗时；不能未经确认把新手术倒填到过去。
- 复杂服务可预约、开始、完成、中断、继续或取消。预约不付款；开工才扣款、接收新件和拆旧；完成不重复收费；继续按剩余时间计算。取消或失败保留已经完成的阶段，不凭空退款、复制实物或复原身体。
- 同一医生可在总信用额度内形成多笔欠款；没有明确约定就不生成固定七天期限。原面板仍显示总欠款和期限文字。

## 原界面和调用成本

`apps/web` 的布局、样式、面板和代码不在修改范围。交易新增事实通过原数据字段和自由输入接入，保持当前用户界面；需要表达预约、订货和复杂条款时可以直接输入文字。

货架查询、按钮交易、正常到货和时间推进由本地代码完成，不增加模型调用。自由输入仍复用判断、正文、抽取；场外经营复用既有场外推演，不为每家商店单开请求。没有改用户预设或加入额外文风规则。未使用真实模型请求，不能据此宣称文学质量提升或给出 token 节省百分比。

## 本轮边界

- 引文校验能检查来源存在、金额和结算条件一致，不能独立证明模型对“谁接受了什么”的语义理解永远正确。正文与结算冲突仍会标记未定稿。
- 本轮没有完整商家经营资金账本和采购偏好，因此普通收购仍不等于真实经济仿真；也未实现自由创建带独立货架的永久商店。临时人物交易走已登记对方与实际持有物。
- 任意以物易物、代购合约、详细订金和退费条款、现实医疗恢复过程不是这三批已经交付的通用系统。
- 原义体面板仍有旧的人性预览文字，独立实物 ID 也不会自动命中前端按型号映射的所有图片。按用户要求本轮不改任何前端文件，运行结算不恢复人性扣减。
- 制作阶段没有添加旧存档迁移或兼容层。当前数据的保存、载入、重放和失败回滚继续验证，用户实际存档未被改写。
