## 四、存档地点簿（第 ③ 层）

### 数据

world 状态里加 `places`（旧存档没有这个字段时当空表）：

```ts
interface SavedPlace {
  id: string; // "place:xxx"，代码生成
  name: string; // 中文名，同名归一
  district: string; // 必填：沃森、威斯特布鲁克……（照 DISTRICT_CENTERS 的名字）
  sub?: string; // 选填：街区名（照 SUBDISTRICT_SHAPES）
  near?: string; // 选填：在哪个已知地点附近（①②③ 的 id 都行）
  note?: string; // 给模型看的一句话
  x: number;
  y: number; // 代码算的
  rough: true | false; // 大概位置；玩家在地图上拖过以后不改（拖过不等于原作入口），另记 movedAt（第二期）
  firstSeenAt: number; // 游戏时间
}
```

### 模型怎么建

- `world` 指令的 `location` 照旧可以写已有 id；写一个表外的地点时，同一轮附一条：
  `{"type": "place", "name": "旧码头 7 号仓库", "district": "沃森", "sub": "北区", "near": "lizzies-bar", "note": "..."}`
- 代码收到后按名字查地点簿：已有就复用 id，没有就建一条，再把 `world.location` 换成这个 id。
- 只写了中文名、没附 `place` 的：照旧存成名字（兼容现在的写法），提示词里提醒模型下轮补上城区。
- `district` 不在城区表里的拒收，退回给模型重写（照现有的指令校验流程）。`sub` 选填（用户定的，2026-10-30）：没写或写错都不拒收、不退回重写，写错的直接丢掉 `sub`，再按下面"坐标怎么定"的顺序往下取（有 `near` 用 `near`，否则城区中心）。恶土、狗镇没有街区轮廓，不写 `sub` 是正常情况。

### 坐标怎么定（模型不给坐标）

按顺序取第一个有的：
1. `near` 指向的地点坐标，往外偏一点（偏移由地点 id 做种子，同一个地方每次算出来一样）；
2. `sub` 街区的标签点（`SUBDISTRICT_SHAPES[].label`）；
3. `district` 城区中心（`DISTRICT_CENTERS`）。

同一格里已有别的点就再错开一点，保证不叠在一起，也不落到城区边界外面（用 `MapPanel.tsx` 里现成的 `inside` 射线判断）。

## 五、原作服务点和商店（第 ② 层）

### 有名有姓的原作店

- `shops.ts` 里的店照旧，每家加一个 `poi` 字段，对到地图上最近的同类图标（例如威尔逊的枪店 → H10 里那个 `gun` 图标）。

- 对不上的（地图上没有同类图标）照旧挂在第 ① 层地点上。

### 其余服务点：空店位

- 没去过的服务点只是地图上的图标，**不进存档、不进提示词**，174 个点不会撑爆上下文。
- 变成真地点的两种方式：
  1. 玩家在地图上点图标 →「去这里」，出行到了就算去过；
  2. 模型写「去日本街找个义体医生」：发 `{"type": "place", "kind": "ripperdoc", "district": "威斯特布鲁克", "sub": "日本街"}`，代码在那个街区挑**最近的、还没被占的**同类图标，换成 `poi:<id>`。街区里没有这一类就往城区里找，再没有就退回给模型（「这一带没有义体医生」）。
- 第一次去时记进地点簿：`{ id: "poi:<id>", name, kind, district, sub, firstSeenAt }`。坐标直接用原作的，`rough: false`。
- 已做（第一期，2026-10-30）：`place` 带 `kind` 的挑点（`places.ts` 的 `applyKind`）。
  - "最近"从哪儿量：玩家就在这个城区时从玩家的位置量，否则从街区标签点或城区中心量（本作改编）。
  - 已进地点簿的不再挑；全都进过了就用最近的那家。
  - 名字只用 `SERVICE_POINTS` 的 `name`，null 时显示"街区 + 类别"（例如"歌舞伎町义体医生"）。
  - 模型写的 `name` 存成 `alias`，提示词里标"本作改编"。

**玩家怎么去**
1. 点地点 → "去这里" → 选择步行、开车或地铁。
2. 代码先检查位置、交通工具、可达性与通行条件，再给路线、预计用时、费用和风险；不能仅凭两点有坐标就判定可达。
3. 玩家确认后开始行程。路途中需要选择或发生遭遇时暂停，由结算代码更新所在路段、时间和资源；走完最后一段才更新为到达目的地。
4. 模型接收路线与结算事实，负责叙事，不得自行瞬移、越过关口或改写已经结算的到达结果。普通 `world.location` 指令也需要纳入位置校验，不能绕开出行规则。

| 方式 | 路线组成                                        | 必须核对                                                   |
| ---- | ----------------------------------------------- | ---------------------------------------------------------- |
| 步行 | 出发点到可步行道路 → 步行路径 → 目的地入口      | 人行通道、楼层、台阶和封闭区域；不能直接套用机动车路网     |
| 开车 | 到车辆 → 可驾车道路 → 合法停车位置 → 步行到入口 | 有可用车辆、道路连通、方向和关口；车不能开进店里           |
| 地铁 | 步行到站 → 乘车及换乘 → 出站后步行到目的地      | 车站入口、线路相邻关系、换乘点；只有车站坐标不足以确定线路 |
