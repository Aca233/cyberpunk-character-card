# 人物创建页：交互逻辑与 UI 设计学习与改造建议

> 范围只限**人物创建表单本身**：两张外部卡如何组织创角页、选项卡、点数、导航、校验、预设和确认页，以及怎样把其中可用的模式迁移到本仓库 `apps/web/src/features/characters/`。不讨论首页协议、状态栏、战斗面板、世界书规则或后端落库。
>
> 证据来源：`.run/card-research/mermaid_remote_build.html`、《创世回廊6.0》远程 Vue 创角单页；`.run/card-research/ver43_custom_start_index.html` / `.pretty.html`、《命定之诗 v4.3》自定义开局单页；本仓库 `CreatorSteps.tsx`、`CreatorLife.tsx`、`CharacterCreator.tsx`、`characters.module.css` 与两张历史创角页截图。

---

## 1. 一句话结论

外部两张卡真正值得学的不是“浅色羊皮纸”或“深青绿卡片”，而是三件事：
1. **把创角看成一套预算驱动的购物车**：所有选择都有价格、剩余点数、禁用原因、确认页汇总；
2. **把长表单拆成可回到原处的“卡片选择 / 详情 / 已选清单”三区结构**，而不是一页里堆满下拉框与说明；
3. **把“快捷预设 / 自由创建 / 草稿 / 导出导入 / 最终确认”做成同一闭环**，让玩家既能 30 秒开档，也能逐项精修。

本仓库已经有赛博朋克原作视觉、8 步结构、主板/联动/旧识/草稿/地图选点，不该换皮成外部卡的浅色奇幻风；应保留 `CellFrame`、红/青/黄原作框和暗色底，只移植**信息架构与反馈机制**。

## 3. 值得学的交互逻辑（按人物创建顺序）

### 3.1 入口：先给玩家一条“快车道”

《创世回廊》进入表单前有一个独立角色选择页：两张大卡——**从零开始创建** vs **预设角色/创意工坊**（`mermaid_remote_build.html:8096-8129`）。预设角色不只是填几个默认值，还会锁定姓名、性别、年龄、种族、职业、技能树、队友、特质，并带完整背景；玩家仍可进入后续步骤查看，但关键字段显示锁定态（`8196-8223, 9209-9217, 9571+`）。

本仓库目前在“出身”步里藏了一个 `ORIGIN_PRESETS`：点出身卡会装配完整主板和属性，并在卡片下出现“基础构筑就绪/直接前往确认档案”（`CreatorSteps.tsx:85-98, 231-260`）。方向相同，但语义混在“出身选择”里：玩家可能以为自己只选了出身，实际整套构筑被替换。

**建议**：把快捷路径提升为创角页顶部/第 1 步的显式选择条，不新增步骤：

```text
[ 空白身份 ] [ 街头小子·扳手 ] [ 流浪者·走私 ] [ 公司员工·潜网 ] [ 导入构筑 ]
                  ↑ 每张卡写明：完整主板、属性、已知风险；点击后显示“已装配，可继续微调 / 直接确认”
```

`applyOriginPreset` 保持不变，只把触发与状态展示从单张出身卡里拆出来，并在覆盖已有自定义构筑前给二次确认。

### 3.2 常驻预算条：把“点数”做成创角的仪表盘

《创世回廊》header 常驻 `AP / RP` 两枚数字，负数变红；所有扣点项都在同一处反映（`mermaid_remote_build.html:7871-7892, 1977-2014`）。《命定之诗》常驻“可用转生点 / 总数”，旁边直接放 `Roll 点数` 与 `预设管理`，负数做抖动，消耗后禁止再 Roll（`ver43_custom_start_index.html:6`；`.pretty.html:227-234`）。确认页再用 4 个指标卡重复“总点/已耗/剩余/命运点”（`.pretty.html:339`）。

本仓库 `budget` 只在 `past/people/skills/cyberware/attributes` 出现，且插在 `stepBody` 内；玩家在“角色特写”“档案确认”看不到背景点/属性点状态，跨步微调时容易忘记预算（`CharacterCreator.tsx:176-197`；`characters.module.css:521-544`）。

**建议**：把点数做成 `creator` 顶部一条**常驻但按步骤降级**的状态栏：
- 用点数的步骤：展开显示 `背景点剩余 12 / 12 · 已花 0 · 返还 0`、`属性点剩余 5 / 5`，并给超支点红色；
- 不用点数的步骤：折叠成两个短徽章 `BP 12` / `AP 5`，点击展开；
- 徽章可点击跳回对应步；
- 每个价格标签统一用 `+N / −N / 返还 N`，不要混用“点数 / 代价 / 系数”。

这能保留现有 `budgetKind` 逻辑，只是把组件从 `stepBody` 提到 `creator` 的 sticky header。

### 3.3 选项卡：卡片必须同时说清“收益、成本、后果、为什么不能选”

外部两套卡都把选项做成**自解释卡**：
- 《创世回廊》世界观光卡片有 icon、副标题、长描述、选中勾，选完立刻给一条“已选择：…”确认带（`mermaid_remote_build.html:8137-8163`）；卡片有 `selected / disabled / card-check / card-icon / card-subtitle / card-footer`（`2288-2408`）。
- 《命定之诗》物品卡有品质顶边、名称、稀有度、详情展开、价格、标签、效果、描述、选择按钮与禁用原因；移动端只展开一个详情，避免整页被长文本撑爆（`ver43_custom_start_index.html:40-43`；`.pretty.html:349-353`）。

本仓库的 `Line k="专长能力/剧情钩子/关联人脉"` 已经接近这个结构，但价格、校验原因和“联动预告”分散在卡片不同位置；旧识、义体、属性页的反馈也不统一。

**建议**：统一一个 `CreatorOptionCard` 契约：

```ts
type CreatorOptionCardProps = {
  title: string;
  eyebrow?: string; // 标签/阵营/品质
  cost?: { label: string; tone: "spend" | "refund" | "free" };
  lines: { label: string; value: ReactNode }[];
  consequence?: ReactNode; // 钩子、代价、联动预告
  selected?: boolean;
  disabled?: boolean;
  disabledReason?: string; // 必须显示，而不是只让按钮变灰
  actions?: ReactNode;
  onSelect?: () => void;
};
```

视觉仍用 `CellFrame`：选中青框、禁用灰化但保留文本、`disabledReason` 放卡片底部小字；卡片右上角固定价格胶囊。这样出身、过往、代价、本事、义体、旧识都能共用一套阅读节奏。

### 3.4 长列表：左列表 / 右详情 / 已选面板，别再整页平铺

《创世回廊》第 2 步的种族是 `200px 左列表 + 右侧详情/属性分配`，左侧列表独立滚动、阵营 Tab 切换；出生点是 iframe 地图；队友用卡片 + 详情弹窗（`mermaid_remote_build.html:8230-8261, 8880-9001, 11138+`）。

《命定之诗》第 2 步更完整：左侧 `category-sidebar`，中间 `filter-area + item-grid`，右侧 `selected-panel`；筛选区 sticky，内容区高度受限且内部滚动，右侧面板显示计数、已消耗点、所有已选项并支持移除/编辑（`ver43_custom_start_index.html:11, 42-45`；`.pretty.html:234, 351-353`）。

本仓库 `skillWall` 是一整页 auto-fill 卡片墙；旧识步已做过“左联系人列表 + 右钉住详情”，是本仓库最接近外部卡优秀实践的一步（`characters.module.css:1410-1508`；`CreatorLife.tsx:269-336`）。

**建议**：只对**条目多**的步骤引入三区布局，不把所有步骤复杂化：

| 本仓库步骤 | 推荐布局                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------ |
| 出身       | 保留 2×2 大卡，外加顶部快捷构筑条                                                                |
| 过往       | 上方“已抽经历”横向摘要 + 抽取/重掷/手选工具条；手选库展开时用左分类/右卡片墙，代价跟在相关经历下 |
| 旧识       | 保留现有左联系人 + 右详情；补“已定关系”小面板与按关系筛选                                        |
| 本事       | 左侧标签/联动筛选 + 中间卡片墙 + 右侧“已插模块 / 联动预告 / 剩余背景点”                          |
| 义体       | 保留原作人体图；部位详情与已装义体清单固定在同一屏，不要靠页面滚动来回找                         |
| 属性       | 表格式五维：`当前 / 基础 / 已投 / 相关本事数 / + −`，右侧常驻推荐与剩余点                        |
| 角色特写   | 四块正文不要平铺成一页；用左侧区块导航 + 右侧编辑器，锁定状态在导航上可见                        |
| 档案确认   | 文档式汇总 + 检查项固定侧栏                                                                      |

### 3.5 点数增减：用 stepper，直接展示最终值

《创世回廊》属性行是 `名称 · 计算说明 · − 数值 +`，按钮在不可加时 disabled（`mermaid_remote_build.html:2211-2285, 8469-8478`）。《命定之诗》更清楚：表头 `属性 / 基础点 / 层级 / 额外点 / 总属性`，每行两个 stepper，底部实时显示“基础点剩余 X / 额外点剩余 Y / ✓ 属性点已全部分配 / ⚠️ 转生点数不足”（`.pretty.html:337`；`ver43_custom_start_index.html:36`）。

本仓库 `StepAttributes` 已有推荐分配，但可借鉴“最终值 = 基础 + 加成 + 已投”的列结构，尤其在 2/5/5 新预算下让每一项变化都可见；同时把“你插的本事里有 2 块靠它”作为该行的关联提示，而不是另写一段说明。

### 3.6 随机与重掷：结果要有仪式，但状态要常驻

本仓库 `StepPast` 做得比外部两套都好：抽取生命路径、翻卡、每段重掷、3 次上限、快速补齐、经历库手选、按出身加权、负面经历“接受，换 N 点”（`CreatorLife.tsx:43-194`）。这是应该保留甚至强化的核心玩法。

可补两点：
- 把“重掷剩余 3 次”从 `stepTitle` 小字提升为工具条上的三段计数点，和 `Roll 点数` 一样常驻；
- 抽出新卡时，在点数条旁边短促显示 `−2 BP`，让“抽卡影响预算”立刻可见；`prefers-reduced-motion` 时只显示文字不翻牌（现有 `.flip` 已遵守 reduced-motion）。

### 3.7 校验：不要只在最后 `alert`，错误要能点回去

《创世回廊》最终页直接列四种状态：`准备就绪` / `还有 N 点属性点未分配` / `RP 点不足` / `请先生成技能树`，点开始旅程时仍再校验一次并 `alert`（`mermaid_remote_build.html:11107-11121, 20000-20063`）。《命定之诗》把总闸收敛成两个条件：未选天赋、可用转生点为负，下一步按钮 disabled 且 `title` 写明原因（`.pretty.html:232-234`）。

本仓库已有 `creatorChecks` 与 `FIELD_STEP`，保存按钮也用 schema `reason` 禁用。缺的是**检查项与页签、卡片之间的视觉回路**：
- 档案确认左侧固定 `8 步检查清单`，每项显示 `✓ / ! / →`；
- 点击 `→` 直接 `goTo(step)`，并把对应卡片/字段滚动到视口、短暂高亮；
- 顶部页签对有错误的步骤显示小圆点，但不强制锁步（保留 aad7c87 后的自由跳步）；
- 禁用按钮的 `reason` 与检查项文案共用同一份 `creatorChecks`，避免“按钮说缺 A、清单说缺 B”。

### 3.8 预设 / 草稿 / 导入导出：把“中途离开”和“重复开档”当一等公民

《创世回廊》顶部“管理预设”弹窗支持命名保存当前配置、导入、列表加载、导出、删除、覆盖确认；配置连世界观、开局、出生点、技能树、评议奖励一起保存（`mermaid_remote_build.html:7897-7930, 13400-13998`）。《命定之诗》有角色卡级 `start_presets` 和聊天级 `custom_start_draft`：800ms 防抖自动存当前 step、自定义表单、注入设置；重进时提示“已恢复上次未完成的开局填写”，失败安全清空；踏上旅程后删草稿（`.pretty.html:122-167, 184-192, 213-218`）。

本仓库草稿只存 `card/step/reached/startLocation/rerolls`；没有保存“手选库是否展开、当前打开哪个模块详情、模型设置”等 UI 状态，也没有构筑预设库（`creator.ts:56-170`）。

**建议分两期**：
1. 低风险：扩展 `CreatorDraft`，增加 `ui: { openPanels, selectedIds, scrollHints }`、`lastSavedAt`；页脚从“草稿自动存在本机”改成“上次保存 17:42 · 已恢复到第 4 步”。
2. 中风险：新增 `cp.creatorPresets`，复用当前 `CharacterCard + startLocation + difficulty` 生成命名构筑；支持导出/导入 JSON、覆盖二次确认、从档案确认页“另存为构筑”。不要直接照抄外部卡把预设塞进角色卡变量；本仓库有 IndexedDB/角色库，应存本地设置数据。

### 3.9 确认页：像“身份档案”，不是表单尾巴

《命定之诗》第 4 步是居中文档：标题“信息确认 / 可结构化的数据会写入 MVU 变量；AI 只接收少量剧情上下文”，下面点数四宫格、基本信息、属性、装备/道具/资产/技能/伙伴/背景分组，品质色直接标在条目名上（`.pretty.html:339`；`ver43_custom_start_index.html:37`）。《创世回廊》第 7 步是“准备就绪”+ 构筑评议结果 + 未完成项，底部才允许“开始旅程”。

本仓库 `StepReview` 已有地图选点、检查项、存档标题、难度、两个保存按钮。建议把信息架构改成两栏：

```text
左：身份档案预览（姓名/外号/出身/属性/主板摘要/旧识数/正文锁定状态/开局地点）
右：合规检查清单 + 保存设置 + 两个主按钮
```

卡片上的每个分组标题都可点回对应步骤；地图选点收进可折叠“开局部署”，默认不挤占首屏。这样“档案确认”才像最终交付物，也更像外部卡的文档式确认页。
